# 🛡️ เช็คก่อนโอน — LINE bot ตรวจเลขบัญชีก่อนโอนเงิน

ผู้ใช้วาง **เลขบัญชีที่กำลังจะโอน** หรือ **ชื่อร้าน/ที่พัก** เข้ามาในไลน์
บอทตอบทันทีว่าบัญชีนั้นเคยมีคนถามถึงมาก่อนไหม พร้อมลิงก์ตรวจสอบต่อ

ใช้ได้กับทุกอย่างที่ต้องโอนเงินก่อน — ที่พัก ของออนไลน์ รถเช่า ทัวร์ ตั๋ว พรีออเดอร์
(เดิมทำเฉพาะที่พักเกาะล้าน ตอนนี้ถอดข้อจำกัดพื้นที่ออกแล้ว หน้า `/koh-larn.html` ยังเก็บไว้เป็นหน้าเจาะกลุ่มเกาะล้านโดยเฉพาะ)

> ⚠️ **ข้อจำกัดที่ต้องบอกผู้ใช้ให้ชัด**
> บอทเป็นเครื่องมือช่วยตรวจเบื้องต้น ไม่ใช่การรับประกัน
> "ไม่พบข้อมูล" ≠ "เป็นมิจฉาชีพ" (อาจแค่ยังไม่ได้ลงทะเบียน)
> ข้อมูลในโฟลเดอร์นี้ตอนนี้เป็น **ข้อมูลสมมติทั้งหมด** ต้องลบก่อนใช้จริง

## 🚀 ทางลัดสำหรับคนไม่เขียนโค้ด — ดับเบิลคลิกอย่างเดียว

ไม่ต้องพิมพ์คำสั่งใด ๆ เปิดโฟลเดอร์ `D:\Kohlarn` แล้วดับเบิลคลิกไฟล์ตามลำดับ

| ไฟล์ | ใช้ตอนไหน | ทำอะไร |
|---|---|---|
| **1-SETUP.bat** | ครั้งแรกครั้งเดียว | ถาม Channel secret + access token แล้วสร้างไฟล์ตั้งค่าให้ |
| **2-START.bat** | ทุกครั้งที่จะใช้งาน | เปิดเซิร์ฟเวอร์ + ngrok แล้วบอก Webhook URL (คัดลอกให้อัตโนมัติ) |
| **3-STOP.bat** | เลิกใช้ | ปิดทุกอย่าง |
| **4-TEST-BOT.bat** | อยากลองเล่น | คุยกับบอทในเครื่อง ไม่ต้องต่อ LINE |
| **5-CONSENT-FORM.bat** | ก่อนลงพื้นที่ | พิมพ์หนังสือยินยอม PDPA ให้เจ้าของที่พักเซ็น |

หลังกด `2-START.bat` จะมีหน้าต่างสีดำเปิดขึ้นมา 2 อัน **ห้ามปิด** —
ปิดเมื่อไหร่บอทหยุดทำงานทันที

ถ้าอยากเข้าใจว่าแต่ละขั้นทำอะไร หรือจะ deploy ขึ้นคลาวด์ อ่านหัวข้อข้างล่างต่อ

## 2. ตั้งค่า LINE Developers Console

### 2.1 สร้าง Provider และ Channel

1. เข้า https://developers.line.biz/console/ แล้วล็อกอิน
2. กด **Create a new provider** ตั้งชื่อ เช่น `Kohlarn Safety` แล้วกด Create
3. ในหน้า Provider กด **Create a Messaging API channel**
   - ⚠️ ต้องเป็น **Messaging API** เท่านั้น ไม่ใช่ LINE Login
4. กรอกข้อมูล:
   - **Channel name** — ชื่อที่ผู้ใช้จะเห็น เช่น `เช็กที่พักเกาะล้าน`
   - **Channel description** — คำอธิบายสั้น ๆ
   - **Category / Subcategory** — เลือก Travel / Travel agency หรือใกล้เคียง
   - **Email address** — อีเมลติดต่อ
5. ติ๊กยอมรับข้อตกลง แล้วกด **Create**

### 2.2 เก็บค่า 2 ตัวที่ต้องใช้

| ค่า | หาได้จาก |
|---|---|
| **Channel secret** | แท็บ **Basic settings** เลื่อนลงหา `Channel secret` |
| **Channel access token** | แท็บ **Messaging API** เลื่อนลงหา `Channel access token (long-lived)` แล้วกด **Issue** |

คัดลอกทั้งสองค่าเก็บไว้ (จะเอาไปใส่ในไฟล์ `.env` ในขั้นตอนถัดไป)

> 🔒 ห้ามเอาค่าสองตัวนี้ไปแปะใน GitHub, กลุ่ม LINE, หรือส่งให้ใคร
> ใครได้ไปจะส่งข้อความในนามบอทคุณได้ทันที
> ถ้าหลุด ให้กลับมาที่หน้านี้แล้วกด **Reissue** ทันที

### 2.3 ปิดระบบตอบกลับอัตโนมัติของ LINE

อยู่ในแท็บ **Messaging API** หัวข้อ `LINE Official Account features`
กด **Edit** (จะเด้งไปหน้า LINE Official Account Manager) แล้วตั้ง:

| หัวข้อ | ตั้งเป็น | เพราะอะไร |
|---|---|---|
| Chat (แชท) | **Off** / ปิด | ไม่งั้นข้อความจะไปเข้าคนตอบแทนบอท |
| Greeting messages | ตามใจ | ข้อความทักทายตอนเพิ่มเพื่อน |
| Auto-reply messages | **Off** / ปิด | ไม่งั้นบอทจะโดนข้อความอัตโนมัติทับ |
| Webhooks | **On** / เปิด | ⭐ สำคัญที่สุด ถ้าไม่เปิดบอทจะไม่ได้รับข้อความเลย |

> ช่อง **Webhook URL** ยังไม่ต้องกรอกตอนนี้ รอ deploy หรือเปิด ngrok ก่อน

## 3. ติดตั้งและรันในเครื่อง

เปิด PowerShell ที่โฟลเดอร์โปรเจกต์ (`D:\Kohlarn`)

### 3.1 ติดตั้ง dependency

```bash
npm install
```

### 3.2 สร้างไฟล์ .env

```bash
copy .env.example .env
```

จากนั้นเปิดไฟล์ `.env` ด้วย Notepad แล้วใส่ค่าที่ได้จากขั้นตอน 2.2:

```
LINE_CHANNEL_ACCESS_TOKEN=ค่ายาว ๆ ที่ copy มาจาก Console
LINE_CHANNEL_SECRET=ค่าสั้นกว่า ที่ copy มาจาก Basic settings
PORT=3000
ADMIN_API_KEY=ตั้งรหัสอะไรก็ได้ที่เดายาก
```

### 3.3 ทดสอบคำตอบของบอท (ยังไม่ต้องต่อ LINE)

วิธีนี้เร็วที่สุดสำหรับดูว่าบอทจะตอบอะไร:

```bash
npm run seed
```

```bash
node scripts/test-chat.js
```

จะเห็นบทสนทนาตัวอย่างพิมพ์ออกมาทั้งชุด ลองข้อความของตัวเองก็ได้:

```bash
node scripts/test-chat.js "ตาแหวนซีวิว"
```

### 3.4 รันเซิร์ฟเวอร์

```bash
npm start
```

ควรเห็นข้อความประมาณนี้:

```
🏝️  kohlarn-verify-bot รันอยู่ที่ http://localhost:3000
    ที่พักในฐานข้อมูล: 10 รายการ (ยืนยันแล้ว 10)
    webhook path: /webhook
```

เปิดเบราว์เซอร์ไปที่ http://localhost:3000/health ควรเห็น JSON `{"ok":true,...}`

> กด `Ctrl + C` ใน PowerShell เพื่อหยุดเซิร์ฟเวอร์

## 4. ทดสอบด้วย ngrok ก่อน deploy จริง

LINE ต้องยิงเข้าเครื่องคุณผ่าน HTTPS แต่ `localhost` เข้าจากข้างนอกไม่ได้
**ngrok** ทำหน้าที่เปิดอุโมงค์ให้ URL สาธารณะชี้มาที่เครื่องเรา

### 4.1 ติดตั้ง ngrok

1. สมัครที่ https://dashboard.ngrok.com/signup
2. โหลดตัวติดตั้งสำหรับ Windows แล้วแตกไฟล์ (หรือใช้ `winget install ngrok.ngrok`)
3. คัดลอก authtoken จาก https://dashboard.ngrok.com/get-started/your-authtoken แล้วรัน:

```bash
ngrok config add-authtoken ค่า_authtoken_ของคุณ
```

### 4.2 เปิดอุโมงค์

**เปิด PowerShell หน้าต่างที่ 1** — รันเซิร์ฟเวอร์ค้างไว้:

```bash
npm start
```

**เปิด PowerShell หน้าต่างที่ 2** — รัน ngrok:

```bash
ngrok http 3000
```

จะเห็นบรรทัด `Forwarding` แบบนี้:

```
Forwarding    https://abcd-1234-5678.ngrok-free.app -> http://localhost:3000
```

คัดลอกส่วน `https://abcd-1234-5678.ngrok-free.app` ไว้

### 4.3 เอา URL ไปใส่ใน LINE Console

1. กลับไปที่ LINE Developers Console → Channel ของคุณ → แท็บ **Messaging API**
2. หัวข้อ **Webhook settings** กด **Edit** ที่ช่อง Webhook URL
3. ใส่ URL ของ ngrok **ตามด้วย `/webhook`**:

   ```
   https://abcd-1234-5678.ngrok-free.app/webhook
   ```

4. กด **Update** แล้วกด **Verify**
   - ✅ ขึ้น `Success` = ถูกต้อง
   - ❌ ขึ้น error = ดูหัวข้อ [แก้ปัญหา](#9-แก้ปัญหาที่เจอบ่อย)
5. เปิดสวิตช์ **Use webhook** ให้เป็นสีเขียว

### 4.4 ทดสอบคุยจริง

1. ในแท็บ **Messaging API** เลื่อนหา **QR code** แล้วสแกนด้วยแอป LINE ในมือถือ
2. กดเพิ่มเพื่อน
3. พิมพ์คุยได้เลย ลอง:

   | พิมพ์ | ควรได้ |
   |---|---|
   | `ช่วยเหลือ` | วิธีใช้งาน |
   | `รายการ` | รายชื่อที่พักที่ยืนยันแล้ว 10 รายการ |
   | `ตาแหวนซีวิว` | ✅ ยืนยันแล้ว + เลขบัญชีที่ถูกต้อง |
   | `123-4-56789-0` | ✅ ยืนยันแล้ว (ค้นจากเลขบัญชี) |
   | `จะโอนมัดจำ 999-9-99999-9` | ⚠️ ไม่พบข้อมูล + 🛑 ข้อความเตือนสติ |

> ⚠️ URL ของ ngrok ฟรีจะ **เปลี่ยนทุกครั้งที่ปิดแล้วเปิดใหม่**
> ต้องกลับมาแก้ Webhook URL ใน Console ใหม่ทุกรอบ
> นี่คือเหตุผลที่ควร deploy ขึ้นคลาวด์เมื่อพร้อมใช้จริง

## 5. Deploy ขึ้น Railway

Railway ใช้ง่ายที่สุดสำหรับ Node.js — ตรวจเจอ `package.json` แล้วรันให้เอง

### 5.1 อัปโค้ดขึ้น GitHub

```bash
git init
```

```bash
git add .
```

```bash
git commit -m "initial: kohlarn verify bot"
```

จากนั้นสร้าง repository **แบบ Private** ที่ https://github.com/new แล้วรันคำสั่งที่ GitHub แสดงให้ (`git remote add origin ...` และ `git push -u origin main`)

> 🔒 ไฟล์ `.env` ถูกใส่ไว้ใน `.gitignore` แล้ว จะไม่ถูกอัปขึ้น GitHub — ถูกต้องแล้ว

### 5.2 สร้างโปรเจกต์บน Railway

1. เข้า https://railway.app แล้วล็อกอินด้วย GitHub
2. กด **New Project** → **Deploy from GitHub repo** → เลือก repo ที่เพิ่งสร้าง
3. รอ build สักครู่

### 5.3 ใส่ Environment Variables

ในหน้าโปรเจกต์ → แท็บ **Variables** → **New Variable** ใส่ทีละตัว:

| ชื่อตัวแปร | ค่า |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | ค่าจาก LINE Console |
| `LINE_CHANNEL_SECRET` | ค่าจาก LINE Console |
| `ADMIN_API_KEY` | รหัสลับที่คุณตั้งเอง |

> ไม่ต้องใส่ `PORT` — Railway กำหนดให้เองอัตโนมัติ

### 5.4 เปิด URL สาธารณะ

แท็บ **Settings** → หัวข้อ **Networking** → กด **Generate Domain**
จะได้ URL แบบ `https://kohlarn-verify-bot-production.up.railway.app`

ทดสอบว่าเซิร์ฟเวอร์ขึ้นแล้ว โดยเปิด `https://<โดเมนของคุณ>/health` ในเบราว์เซอร์

### 5.5 ตั้ง Webhook URL

กลับไป LINE Console → Messaging API → Webhook URL ใส่:

```
https://<โดเมนของคุณ>/webhook
```

กด **Update** → **Verify** → เปิด **Use webhook**

> ⚠️ **ข้อจำกัดสำคัญของ Railway/Render กับฐานข้อมูล JSON**
> ไฟล์ `data/db.json` จะถูก **รีเซ็ตกลับเป็นข้อมูลตัวอย่างทุกครั้งที่ deploy ใหม่**
> เพราะระบบสร้าง container ใหม่ทั้งใบ ที่พักที่ลงทะเบียนผ่าน `/register` จะหาย
> ใช้ทดสอบได้ แต่ก่อนใช้งานจริงจริงจัง ควรย้ายไป Postgres (Railway มีให้กดเพิ่มฟรี)
> หรือใช้ Railway **Volume** เมานต์ที่ path `/app/data`

## 6. Deploy ขึ้น Render (ทางเลือก)

1. เข้า https://render.com ล็อกอินด้วย GitHub
2. **New +** → **Web Service** → เลือก repo
3. ตั้งค่า:

   | ช่อง | ใส่ |
   |---|---|
   | Environment | `Node` |
   | Build Command | `npm install` |
   | Start Command | `npm start` |
   | Instance Type | `Free` |

4. หัวข้อ **Environment Variables** ใส่ `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`, `ADMIN_API_KEY`
5. กด **Create Web Service** รอ deploy เสร็จ จะได้ URL `https://xxx.onrender.com`
6. เอา `https://xxx.onrender.com/webhook` ไปใส่ใน LINE Console

> ⚠️ **Render free tier จะหลับเมื่อไม่มีคนใช้ 15 นาที**
> ข้อความแรกหลังหลับจะช้า ~30–50 วินาที และ LINE อาจ timeout
> แก้ได้โดยตั้ง cron ping `/health` ทุก 10 นาที (เช่นด้วย https://cron-job.org ฟรี)
> ถ้ารับไม่ได้ ใช้ Railway จะราบรื่นกว่า

## 7. API สำหรับลงทะเบียนที่พักใหม่

### 🌐 หน้าเว็บ (วิธีปกติ)

| หน้า | URL | ใครใช้ |
|---|---|---|
| หน้าแรก (ชวนใช้บอท) | `https://<โดเมนของคุณ>/` | นักท่องเที่ยว — ลิงก์นี้คือลิงก์ที่เอาไปแชร์ |
| ฟอร์มลงทะเบียน | `https://<โดเมนของคุณ>/register.html` | เจ้าของที่พัก กรอกเอง |
| หน้าผู้ดูแล | `https://<โดเมนของคุณ>/admin.html` | คุณ ไว้กดยืนยัน |

**ก่อนเปิดให้คนนอกใช้ ต้องกรอก 2 ค่านี้ใน `.env` ก่อน** ไม่งั้นหนังสือยินยอมจะไม่สมบูรณ์ตาม PDPA:

```
ORG_NAME=ชื่อคุณหรือชื่อกลุ่มที่ดูแลระบบ
ORG_CONTACT=อีเมลหรือเบอร์ให้เจ้าของที่พักติดต่อขอลบข้อมูล
LINE_OA_ID=@ไอดีบอทของคุณ
```

`LINE_OA_ID` ดูได้ที่ LINE Developers Console → แท็บ **Messaging API** → หัวข้อ **Bot basic ID**
ใส่แล้วหน้าแรกจะมีปุ่ม "เพิ่มเพื่อน" ที่กดได้จริง และบอทจะแนบลิงก์ส่งต่อให้เพื่อนท้ายทุกข้อความเตือน

**ขั้นตอนใช้งานจริง**

1. ส่งลิงก์ฟอร์มให้เจ้าของที่พัก (หรือให้เขาสแกน QR ตอนลงพื้นที่)
2. เขากรอก ติ๊กยินยอม กดส่ง → ได้รหัส `KL-0xx` ไว้อ้างอิง
3. คุณเปิด `/admin.html` ใส่ `ADMIN_API_KEY` → เห็นรายการรอตรวจ
4. **โทรเช็กตัวจริงก่อนเสมอ** แล้วค่อยกด ✅ ยืนยัน เผยแพร่
5. บอทถึงจะเริ่มตอบว่า "ยืนยันแล้ว" ให้ที่พักนั้น

**หนังสือยินยอมแบบกระดาษ** (สำหรับลงพื้นที่ ไม่มีเน็ต) — กด `5-CONSENT-FORM.bat` จะได้ไฟล์ `docs/consent-form.txt` พิมพ์ออกมาให้เซ็นได้เลย ทำ 2 ชุด เก็บเอง 1 ให้เจ้าของ 1

> 🔐 **ทำไม `/register` ถึงเปิดสาธารณะได้โดยไม่ต้องมีรหัส**
> เพราะเจ้าของที่พักต้องกรอกเองได้ ความปลอดภัยมาจาก 3 ชั้นแทน:
> 1. ทุกรายการเข้ามาเป็น "รอยืนยัน" บอทยังไม่บอกว่ายืนยันแล้ว
> 2. ต้องผ่านคนกดยืนยันก่อนเผยแพร่
> 3. จำกัด 5 ครั้ง/ชั่วโมง/IP + ช่องดักบอท
>
> ส่วน `/admin/*` ถ้าไม่ตั้ง `ADMIN_API_KEY` ระบบจะ**ปิดทั้งหมด** ไม่ใช่เปิดโล่ง

### POST /register

ที่พักที่ลงทะเบียนเข้ามาจะมีสถานะ **`verified: false` (รอยืนยัน) เสมอ**

> 🔐 **นี่คือจุดสำคัญด้านความปลอดภัย** — ถ้าลงทะเบียนแล้วขึ้น "ยืนยันแล้ว" ทันที
> มิจฉาชีพจะเอาเลขบัญชีตัวเองมาลงทะเบียน แล้วใช้บอทของเราเป็นตรารับรองความน่าเชื่อถือ
> จึงต้องมีคนตรวจก่อนเสมอ

ตัวอย่างเรียกจาก PowerShell:

```bash
curl.exe -X POST http://localhost:3000/register -H "Content-Type: application/json" -H "x-api-key: รหัสลับของคุณ" --data-binary "@sample-register.json"
```

รูปแบบ JSON ที่ส่ง:

```json
{
  "name": "ชื่อที่พัก",
  "bankName": "ธนาคารกสิกรไทย",
  "accountNumber": "111-2-33344-5",
  "accountName": "ชื่อเจ้าของบัญชี",
  "facebookPage": "https://www.facebook.com/yourpage",
  "phone": "081-234-5678",
  "gps": { "lat": 12.9297, "lng": 100.7817 },
  "beach": "หาดตาแหวน",
  "aliases": ["ชื่อเล่นที่คนเรียก", "english name"]
}
```

| ฟิลด์ | บังคับ | หมายเหตุ |
|---|---|---|
| `name` | ✅ | อย่างน้อย 2 ตัวอักษร |
| `accountNumber` | ✅ | อย่างน้อย 8 หลัก (ขีดคั่นได้) |
| `accountName` | ✅ | ชื่อเจ้าของบัญชี |
| `phone` | ✅ | อย่างน้อย 9 หลัก ผู้ดูแลใช้โทรตรวจสอบ |
| `reporterName` | ✅ | ชื่อผู้กรอก ไม่เผยแพร่ต่อสาธารณะ |
| `reporterRole` | ✅ | เกี่ยวข้องกับที่พักอย่างไร |
| `consent` | ✅ | ต้องเป็น `true` ไม่งั้นเก็บข้อมูลไม่ได้ตาม PDPA |
| `facebookPage`, `gps`, `beach`, `bankName`, `aliases` | ไม่บังคับ | แต่ใส่ให้ครบจะตรวจง่ายขึ้นมาก |

ระบบจะบันทึกหลักฐานการยินยอมให้อัตโนมัติ: `consentAt` (เวลา), `consentVersion` (ฉบับที่เซ็น), `consentIp`

การตอบกลับ:

| สถานะ | ความหมาย |
|---|---|
| `201` | ลงทะเบียนสำเร็จ (สถานะรอยืนยัน) |
| `400` | ข้อมูลไม่ครบ — ดูรายละเอียดในฟิลด์ `errors` |
| `409` | เลขบัญชีนี้มีในระบบแล้ว |
| `401` | `x-api-key` ผิด |

## 7.5 ความจำร่วม — ทำไมบอทถึงมีประโยชน์ทั้งที่ยังไม่มีใครลงทะเบียน

ทุกครั้งที่มีคนถามบอทด้วยเลขบัญชี ระบบจดไว้ว่า "เคยเห็นเลขนี้" แล้วครั้งต่อไปตอบได้ว่า
เลขนั้นเคยมีคนถามมาก่อนกี่ครั้ง ครั้งแรกเมื่อไหร่

| สิ่งที่เห็น | บอทตอบว่า | เพราะอะไร |
|---|---|---|
| ไม่เคยมีใครถาม | 🆕 ระวังเป็นพิเศษ | บัญชีของที่พักที่เปิดมานาน มักเคยมีคนถามแล้ว |
| ถูกถาม 5+ ครั้งใน 14 วัน | 🚨 ผิดปกติ อย่าเพิ่งโอน | รูปแบบของการหว่านหลอกหลายคนพร้อมกัน |
| ถูกถามกระจายตัวเกิน 4 เดือน | 📊 มีประวัติมานาน | บัญชีที่ใช้จริงมานาน (แต่ยังไม่ใช่การยืนยัน) |

**ข้อมูลโตเองจากคนใช้งาน ไม่ต้องรอเจ้าของที่พักมาลงทะเบียน**

### เรื่องความเป็นส่วนตัว

ระบบ**ไม่เก็บเลขบัญชีที่ผู้ใช้พิมพ์เข้ามา** เก็บเฉพาะค่าแฮชแบบทางเดียว (HMAC-SHA256 + salt ลับ)
ซึ่งใช้เทียบว่า "เลขนี้เคยเจอไหม" ได้ แต่ถอดกลับเป็นเลขบัญชีไม่ได้
ต่อให้ไฟล์ฐานข้อมูลหลุด ก็ไม่มีเลขบัญชีของใครรั่วออกไป

⚠️ ไฟล์ `data/salt.txt` **ห้ามลบและห้ามขึ้น git** ถ้า salt เปลี่ยน ประวัติทั้งหมดเทียบไม่ได้อีก

## 7.6 หน้าเว็บล่าคีย์เวิร์ด (SEO)

หน้าเว็บพวกนี้มีไว้ให้คนหาเจอเองจาก Google โดยคุณไม่ต้องไปโพสต์หรือทักใคร

`robots.txt` และ `sitemap.xml` สร้างอัตโนมัติ (`/admin.html` ถูกกันไม่ให้ Google เก็บ)

### หลัง deploy ต้องทำ 2 อย่าง ไม่งั้น Google ไม่เก็บ

1. ใส่ `BASE_URL` ใน `.env` เป็นโดเมนจริง — ใช้ `6-ORG-INFO.bat` กรอกได้
2. ส่ง sitemap เข้า [Google Search Console](https://search.google.com/search-console) → เพิ่ม property → วาง `https://<โดเมน>/sitemap.xml`

โดยปกติใช้เวลาหลายสัปดาห์กว่าจะเริ่มติดอันดับ ไม่ใช่ทันที

## 10. ข้อควรระวังเรื่องข้อมูลและกฎหมาย

ระบบนี้เก็บและเผยแพร่ **เลขบัญชีธนาคารและชื่อบุคคล** ซึ่งเป็นข้อมูลส่วนบุคคล
ก่อนเปิดใช้จริงกับที่พักจริง ควรทำอย่างน้อยดังนี้:

1. **ขอความยินยอมเป็นลายลักษณ์อักษร** จากเจ้าของที่พักทุกราย
   ว่ายอมให้เผยแพร่ชื่อบัญชี/เลขบัญชีผ่านบอท (PDPA)
2. **ลบข้อมูลตัวอย่างทั้งหมด** ใน `src/data/accommodations.seed.json` ทิ้งก่อน
   ข้อมูลชุดนั้นเป็นข้อมูลสมมติล้วน
3. **ห้ามให้บอทระบุว่าใครเป็นมิจฉาชีพ** — ข้อความปัจจุบันจงใจใช้คำว่า
   "ไม่พบข้อมูลในระบบ" ไม่ใช่ "รายนี้เป็นมิจฉาชีพ" เพราะการกล่าวหาผิดตัว
   เสี่ยงคดีหมิ่นประมาท ถ้าจะแก้ข้อความในไฟล์ `messages.js` ให้ระวังจุดนี้
4. **มีช่องทางให้เจ้าของที่พักขอแก้ไข/ลบข้อมูลตัวเอง** ได้
5. **ตั้ง `ADMIN_API_KEY` เสมอบน production** ไม่งั้นใครก็ยิงข้อมูลเข้าระบบได้
6. เก็บ log การยืนยัน (ใคร ยืนยันรายการไหน เมื่อไหร่) ไว้ตรวจย้อนหลัง
